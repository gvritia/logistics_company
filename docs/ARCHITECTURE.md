# Архитектура и её развитие

Текущий этап — фундамент проекта. Схемы ниже задают границы будущих компонентов и не означают наличия реализации.

## КР1: Console

```text
Console UI
   ↓
Service
   ↓
Repository / JDBC
   ↓
PostgreSQL
```

Console UI получает ввод и показывает результат. Service проверяет бизнес-правила и координирует операции. Repository инкапсулирует JDBC и SQL. Сущности и собственные исключения не должны зависеть от консольного меню.

Существующий `pom.xml` и `src/` временно остаются в корне. Новый код КР1 будет находиться под `src/main/java/com/logisticscompany/console/`: `app`, `model`, `repository`, `service`, `exception`, `config`, `export`, `util`. Пока эти пакеты содержат только маркеры структуры.

## КР2: JavaFX

```text
JavaFX View / FXML
   ↓
Controller
   ↓
Service
   ↓
Repository / DAO / JDBC
   ↓
PostgreSQL
```

`javafx-client/` — отдельное desktop-приложение. Controller связывает представление с сервисами; FXML и CSS определяют интерфейс. SQL и бизнес-правила не помещаются в Controller или FXML.

КР2 должна продемонстрировать самостоятельную работу JavaFX с БД через JDBC. Backend появится только в КР3, поэтому REST не является зависимостью КР2. Переход JavaFX на REST не выполняется автоматически с началом КР3: для него понадобится отдельное требование и решение.

Бизнес-правила должны оставаться согласованными с КР1. Перед повторным использованием кода необходимо оценить выделение уже существующих независимых сервисов и моделей. Общая библиотека сейчас не создаётся; копирование одной бизнес-логики в несколько UI не считается решением.

## КР3: Spring REST Backend

```text
Web / API Clients
   ↓ HTTP / REST
REST Controller
   ↓
Spring Service
   ↓
Spring Data JPA
   ↓
PostgreSQL
```

`backend/` — отдельный Spring Boot компонент. Controllers принимают и возвращают DTO, сервисы реализуют правила и координацию, JPA repositories работают с хранением. Security, валидация и единая обработка ошибок оформляются в предусмотренных для них пакетах, когда начнётся КР3.

Backend использует схему, выросшую из КР1. Flyway становится механизмом её изменения, а Hibernate запускается с `ddl-auto: validate`. План перехода уже существующей БД на Flyway нужно подготовить до подключения миграций.

При необходимости web-ресурсы размещаются в `backend/src/main/resources/static/`; отдельный SPA проект сейчас не предусмотрен.

## КР4: Android

```text
Android (Java 17 source level)
   ↓ HTTP / REST
Spring Boot backend
   ↓
PostgreSQL
```

Android использует API backend КР3 через Retrofit / OkHttp / Gson. Прямой доступ к PostgreSQL не допускается: работа с данными, проверка прав и бизнес-правила проходят через backend, а реквизиты БД не передаются мобильному клиенту. Android-проект будет создан в Android Studio; текущий каталог содержит только README.

## Границы монорепозитория

| Путь | Назначение сейчас и в будущем |
| --- | --- |
| `pom.xml`, `src/` | Существующий Maven-проект и место реализации КР1 до безопасного переноса |
| `console-app/` | Резерв будущего отдельного консольного модуля; сейчас только README |
| `javafx-client/` | Каркас каталогов КР2 без Maven-конфигурации и приложения |
| `backend/` | Каркас каталогов КР3 без Spring Boot конфигурации и приложения |
| `android-client/` | README для будущего проекта КР4 |
| `database/` | Будущие SQL scripts и диаграммы, общие для развития схемы |
| `infra/` | Место будущих Docker и служебных файлов; без действующего развёртывания |
| `docs/` | Контекст, требования, решения и backlog |

Корневой Maven-проект сейчас не является агрегатором. Заготовки будущих компонентов не подключены к сборке. Причины сохранения текущих путей описаны в [DECISIONS.md](DECISIONS.md).
