# Архитектурные решения

Простой ADR-реестр. `Accepted` фиксирует договорённость о структуре или будущем подходе, но не означает готовой реализации. Изменение решения оформляется отдельной задачей и отражается в связанных документах.

## ADR-001 — Монорепозиторий

**Status: Accepted**

**Decision:** Все компоненты КР1–КР4, документация, схема БД и инфраструктурные файлы находятся в одном репозитории.

**Reason:** Четыре контрольные работы составляют один сквозной проект команды из четырёх разработчиков и развивают общую предметную область и БД.

## ADR-002 — PostgreSQL

**Status: Accepted**

**Decision:** Использовать PostgreSQL на всех этапах. КР1 и КР2 работают через JDBC, КР3 — через Spring Data JPA.

**Reason:** Единая СУБД сохраняет преемственность данных и схемы при смене клиентских технологий.

## ADR-003 — Java 21

**Status: Accepted**

**Decision:** КР1, КР2 и backend КР3 используют Java 21; JavaFX — версии 21. Android имеет отдельный уровень исходников 17.

**Reason:** Это технологическая база задания. Различие Android не меняет целевую версию Java серверных и desktop-компонентов.

## ADR-004 — Maven

**Status: Accepted**

**Decision:** Использовать Maven 3.9+ для КР1, КР2 и backend КР3; Gradle предназначен для Android. Сейчас сохраняется действующий корневой Maven-проект, без агрегатора и фиктивных модулей.

**Reason:** Существующая сборка должна оставаться рабочей. Build-конфигурации будущих приложений добавляются при начале соответствующей КР.

## ADR-005 — Java для Android

**Status: Accepted**

**Decision:** Android-клиент пишется на Java с source compatibility 17 и создаётся в Android Studio на этапе КР4. Сейчас в `android-client/` находится только README.

**Reason:** Требования предусматривают Java и Gradle; преждевременный Gradle-каркас не подтверждает готовность Android-проекта.

## ADR-006 — Базовый package

**Status: Accepted**

**Decision:** Новый Java-код размещается под `com.logisticscompany` с подпространствами `console`, `javafx` и `backend`. Названия университета, включая `ru.mirea`, не используются в package.

**Reason:** Имена отражают предметную область и назначение компонентов. Существующий класс `org.exaple.Main` пока сохраняется; его миграция не смешивается с подготовкой структуры.

## ADR-007 — Отдельный JavaFX-клиент

**Status: Accepted**

**Decision:** `javafx-client/` станет отдельным приложением КР2 и будет обращаться напрямую к PostgreSQL через JDBC, через слои Controller → Service → Repository/DAO.

**Reason:** КР2 требует самостоятельного desktop-приложения до появления REST backend. Начало КР3 не означает автоматический перевод JavaFX на REST.

## ADR-008 — Отдельный Spring backend

**Status: Accepted**

**Decision:** `backend/` зарезервирован для Spring Boot КР3. Возможный web-интерфейс размещается в `src/main/resources/static/` этого компонента; отдельный SPA проект без запроса не создаётся.

**Reason:** Backend обслуживает REST-клиентов и имеет собственные DTO, security и JPA-слои, которые не нужны приложениям КР1 и КР2.

## ADR-009 — Android через REST

**Status: Accepted**

**Decision:** Android использует backend КР3 через Retrofit / OkHttp / Gson. Прямое подключение к PostgreSQL запрещено.

**Reason:** Контракт API, проверка прав и бизнес-правила сосредоточены в backend; мобильному приложению не передаются реквизиты БД.

## ADR-010 — Развитие схемы через Flyway с КР3

**Status: Accepted**

**Decision:** SQL scripts КР1 находятся в `database/`, а схема КР1 служит основой КР3. С КР3 изменения выполняются Flyway; Hibernate использует `ddl-auto: validate`.

**Reason:** Управляемая история изменений должна сохранять накопленные данные. Переход существующей БД на Flyway требует отдельного плана baseline и миграций; сейчас SQL и миграции не создаются.

## ADR-011 — Отложенный перенос существующего Maven-проекта

**Status: Accepted**

**Decision:** Корневые `pom.xml` и `src/` остаются на месте. `console-app/` пока содержит README о будущем переносе; новый каркас пакетов КР1 находится в `src/main/java/com/logisticscompany/console/`.

**Reason:** В исходном состоянии tracked `.idea/misc.xml` ссылается на корневой POM, а `logistics_company.iml` — на корневые source directories. Есть пользовательский untracked `.idea/encodings.xml` со ссылками на корневой `src`. Перенос потребовал бы согласованного изменения этих настроек и затронул бы пользовательскую конфигурацию. Сохранение работающей сборки и настроек важнее немедленного совпадения с целевым деревом.

**Consequences:** Команды Maven выполняются из корня. Безопасный перенос через `git mv`, обновление путей с учётом пользовательских настроек и проверка сборки из `console-app/` остаются отдельной задачей в [TASKS.md](TASKS.md). До него нельзя создавать второй конкурирующий console Maven-проект.

## ADR-012 — Сохранение исходного кода и координат

**Status: Accepted**

**Decision:** Существующий пустой класс `org.exaple.Main` и Maven-координаты `org.example:my-project:1.0-SNAPSHOT` остаются без изменений. Новая структура не добавляет бизнес-классы и зависимости.

**Reason:** Foundation не должна менять поведение или ломать существующие ссылки. Переименование класса/package и координат можно выполнить отдельным согласованным рефакторингом с проверкой сборки.

## ADR-013 — Предварительные статусы заявки

**Status: Proposed**

**Decision:** Для будущего `TransportationRequestStatus` предложены `CREATED`, `APPROVED`, `IN_TRANSIT`, `DELIVERED`, `CANCELLED`.

**Reason:** Набор даёт отправную точку для модели КР1, но статусы и допустимые переходы должны быть уточнены до реализации. Enum пока существует только в документации.

## ADR-014 — Последовательная реализация и общая логика

**Status: Accepted**

**Decision:** Сейчас создаются только структура и документы. UI, Service и Repository разделяются при реализации; общая библиотека не создаётся до появления обоснованной потребности. Повторное использование бизнес-правил КР1 для КР2 проектируется до их копирования.

**Reason:** Преждевременные зависимости усложняют учебные этапы, а дублирование правил приводит к расхождениям между интерфейсами.
