# Разработка и локальная проверка

## Инструменты

- JDK 21 для КР1, КР2 и backend КР3.
- Maven 3.9+ для Java-компонентов. Сейчас существует только корневой POM КР1.
- PostgreSQL потребуется при реализации БД КР1; версия будет согласована
  перед подготовкой схемы и окружения.
- JavaFX 21 потребуется в КР2, Spring Boot — в КР3. Зависимости пока не добавлены.
- В КР4 Android создаётся в Android Studio: Java, source compatibility 17,
  Gradle. Требования к JDK сборки и версии SDK/AGP уточняются отдельно:
  source level приложения не определяет автоматически JDK для запуска Gradle.

Используйте любую удобную IDE или редактор. Источник истины для существующей
сборки — `pom.xml`, а не настройки IntelliJ IDEA. Кодировка — UTF-8;
отступы и окончания строк новых файлов описывают `.editorconfig` и
`.gitattributes`. Массовая перезапись старых файлов не требуется.

## Подготовка

1. Клонируйте репозиторий и создайте ветку задачи по [Git workflow](GIT_WORKFLOW.md).
2. Настройте `JAVA_HOME` на JDK 21; добавьте Maven и при необходимости
   `JAVA_HOME/bin` в `PATH`.
3. Выполните из корня:

   ```sh
   mvn -version
   mvn -B test
   ```

`mvn -version` должен показывать Maven 3.9+ и Java 21. Maven может работать
через `JAVA_HOME`, даже если команда `java` отдельно недоступна в `PATH`.
При первом запуске потребуется доступ к репозиторию Maven для плагинов.
Maven Wrapper пока отсутствует.

## Что проверяется сейчас

Существующий POM компилирует исходную пустую заготовку `org.exaple.Main`.
Тестовых классов и запускаемой точки входа пока нет. `mvn -B test`
проверяет сборку и запускает тесты, когда они появятся; успех сейчас
не означает наличие проверенной бизнес-функциональности.

Для полной пересборки можно выполнить `mvn -B clean test`; эта команда
удаляет генерируемый `target/`, где нельзя хранить пользовательские файлы.
Перед созданием foundation исходная проверка `mvn -B test` завершилась
успешно на Maven 3.9.16 / Java 21.0.12.

`console-app/` пока содержит только README. Проверку выполняйте из корня,
а не из этого каталога. JavaFX, backend и Android пока не имеют сборочных
проектов, поэтому команд запуска для них ещё нет. Существующие настройки
IDE сохранены; новый разработчик может импортировать корневой POM.

## Конфигурация и данные

`.env.example` — документационный шаблон для будущих настроек PostgreSQL
и backend. Сейчас нет загрузчика `.env`, контейнеров или подключения к БД.
Не требуется создавать `.env` или поднимать PostgreSQL ради сборки каркаса.
Когда конфигурация будет реализована, локальные значения сохраняются в
игнорируемом `.env`, реальные пароли и JWT secrets не коммитятся.

SQL КР1 появится в `database/`; миграции КР3 — в
`backend/src/main/resources/db/migration/`. Эти каталоги пока содержат
только маркеры. Правила развития схемы: [DATABASE.md](DATABASE.md).

## Качество и проверка изменений

- Перед задачей прочитайте документы в порядке из [AGENTS.md](../AGENTS.md).
- Работайте в рамках текущей КР и одной задачи; соблюдайте границы UI,
  Service и Repository. SQL не должен находиться в UI.
- Не добавляйте библиотеки без конкретной потребности и не создавайте
  дублирующие реализации бизнес-правил. Общий модуль выделяется только
  отдельным обоснованным решением.
- Перед коммитом проверьте `git diff --check`, `git diff --cached`
  и выполните `mvn -B test` для текущего Maven-проекта. В дальнейшем добавляйте
  проверки, соответствующие изменённому компоненту.
- Проверьте `git status --short --branch` и игнорирование секретов:
  `git check-ignore -v --no-index .env .env.local`. Для `.env.example`
  `git check-ignore -q --no-index .env.example` должен возвращать код 1
  (файл не игнорируется).
- Не добавляйте `target/`, локальные настройки IDE и реальные данные.
  Уже отслеживаемые настройки IDE сохранены; `.gitignore` не удаляет их
  из истории и индекса.
- Изменение архитектуры сопровождайте обновлением документации и ADR.
  Результат проверки и ограничения указывайте в Pull Request.
