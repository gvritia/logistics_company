# Предварительная предметная модель

Модель описывает будущую систему логистической компании. Классы, enum и таблицы на этапе foundation не создаются. Поля, ограничения и правила необходимо уточнить перед реализацией КР1.

## Уже требуется

«Требуется» означает наличие требования КР1, а не готового кода.

| Элемент | Назначение | Предварительные сведения |
| --- | --- | --- |
| `TransportationRequest` | Заявка на перевозку груза, основная сущность | Идентификатор, клиент, сведения о грузе и маршруте, статус; точные поля предстоит согласовать |
| `Client` | Клиент, размещающий заявки | Идентификатор, имя/наименование и контактные сведения; формат и обязательность уточняются |
| `TransportationRequestStatus` | Статус заявки | Предварительный enum с ограниченным набором значений |

### Статусы заявки

Рабочее предложение для `TransportationRequestStatus`:

```text
CREATED
APPROVED
IN_TRANSIT
DELIVERED
CANCELLED
```

Смысл значений: создана, одобрена, в пути, доставлена, отменена. Это предварительное архитектурное решение, которое можно скорректировать до реализации КР1. Допустимые переходы, условия отмены и завершения ещё не утверждены и не являются готовой бизнес-логикой.

### Отношения

Предварительно один `Client` может иметь несколько `TransportationRequest`, а каждая заявка относится к одному клиенту. Правила удаления клиента с заявками, изменения привязки и хранения истории должны быть определены вместе со схемой БД. Автоматическое каскадное удаление не предполагается без отдельного решения.

Минимум пять бизнес-правил КР1 предстоит явно сформулировать и проверить в Service. Необходимо отдельно согласовать обязательные данные заявки, допустимые значения, проверки клиента и ограничения изменения статуса; этот документ не подменяет их спецификацию.

## Вероятно потребуется в следующих КР

| Элемент | Возможное назначение |
| --- | --- |
| `CargoType` | Справочник типов груза, если простого описания недостаточно |
| `UserAccount` | Учётные записи и роли backend КР3 |
| `RefreshSession` | Сессии обновления токенов backend КР3 |
| `TransportationRequestNote` | Заметки/комментарии к заявке |
| `Tag` | Метки и группировка заявок |
| `AuditEvent` | Аудит действий и изменений |

Возможные отношения: заявка имеет несколько заметок, заявка связана с несколькими тегами, пользователь имеет несколько refresh sessions. Точная модель пользователей, аудита и связей проектируется на этапе КР3. Права доступа, JWT и аудит не включаются в КР1 заранее.

Модель должна развиваться совместно со [схемой БД](DATABASE.md). JPA-аннотации и API DTO появятся в backend КР3; они не нужны для текущего каркаса и не должны навязывать зависимости консольному или JavaFX-приложению.
