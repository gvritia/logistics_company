# База данных

СУБД проекта — PostgreSQL. На этапе foundation схема, SQL scripts, seed data, подключения и миграции ещё не реализованы.

## Доступ по этапам

| Этап | Способ работы с данными |
| --- | --- |
| КР1 | Console → Service → Repository / JDBC → PostgreSQL |
| КР2 | JavaFX → Controller → Service → Repository / DAO / JDBC → PostgreSQL |
| КР3 | REST → Spring Service → Spring Data JPA → PostgreSQL |
| КР4 | Android → REST backend КР3; доступа Android к БД нет |

В КР1 и КР2 SQL размещается в слое Repository/DAO и выполняется с параметрами через `PreparedStatement`. SQL не должен попадать в консольное меню или JavaFX Controller.

## Каталоги

- `database/schema/` — будущие SQL scripts создания и согласованного развития схемы КР1/КР2.
- `database/seed/` — будущие обезличенные демонстрационные данные; реальные персональные данные и секреты не допускаются.
- `database/diagrams/` — будущие ER-диаграммы и пояснения связей.
- `backend/src/main/resources/db/migration/` — будущие миграции Flyway, начиная с КР3.

Сейчас назначение каталогов закреплено документацией и маркерами; содержательных SQL-файлов в них нет.

## Преемственность схемы

Схема КР1 становится базой для КР2 и КР3. На старте КР1 нужно согласовать сущности, ключи, связи, ограничения и правила удаления, затем зафиксировать схему в `database/schema/`.

Начиная с КР3 изменения схемы выполняются через Flyway. До его внедрения команда должна описать переход: как зафиксировать исходную схему, инициализировать новую БД и подключить уже существующую БД с сохранением данных. Baseline и первая миграция не создаются автоматически в текущей задаче.

Для backend принято значение Hibernate `ddl-auto: validate`. Hibernate проверяет соответствие модели схеме; создание и изменение таблиц остаётся ответственностью миграций. Не следует независимо менять одну схему через Hibernate, ручной SQL и Flyway.

## Локальная конфигурация

Реальные пароли, URL с паролями и секреты не хранятся в Git. Корневой `.env.example` — только шаблон с placeholders; `.env` и локальные данные PostgreSQL игнорируются Git. `POSTGRES_PORT=55432` в шаблоне обозначает предполагаемый локальный порт и не означает, что контейнер или БД уже настроены.

Maven и Java сами по себе не читают `.env`: загрузку конфигурации нужно явно реализовать в соответствующей будущей задаче. Наличие шаблона не создаёт подключения к БД.
