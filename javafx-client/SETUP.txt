КР2: JavaFX-клиент логистической компании

Требуются Java 21, Maven 3.9+ и запущенный Docker Desktop.
Скопируйте корневой .env.example в .env и задайте собственный POSTGRES_PASSWORD.
Для Docker используются POSTGRES_HOST=127.0.0.1 и POSTGRES_PORT=55432.

Основной способ запуска на Windows из корня репозитория:
  powershell -ExecutionPolicy Bypass -File .\javafx-client\run.ps1

Скрипт запускает PostgreSQL в Docker, собирает зависимость КР1 и затем
выполняет Maven-цель javafx:run для настольного клиента.

Запуск из IntelliJ IDEA:
  1. Добавьте javafx-client/pom.xml как Maven-проект и дождитесь загрузки зависимостей.
  2. Выберите для проекта JDK 21. Если зависимости КР1 ещё нет в локальном
     Maven-репозитории, выполните в корне репозитория mvn install.
  3. Запускайте цель Maven javafx:run из javafx-client. Для обычной
     конфигурации Java Application используйте com.lcorp.javafx.Launcher.
     Не запускайте com.lcorp.javafx.Main напрямую: стандартный
     Java launcher требует для такого класса особой настройки JavaFX runtime.
  4. Укажите рабочую папку запуска javafx-client. Приложение найдёт корневой .env.

При первом создании Docker volume PostgreSQL автоматически выполняет SQL-схему
и seed КР1 из database/. При повторном запуске данные сохраняются.
Проверка контейнера:
  docker compose --env-file .env -f infra/docker/compose.kr2.yml ps
Остановка без удаления данных:
  docker compose --env-file .env -f infra/docker/compose.kr2.yml down

Если нужно перенести уже существующую БД КР1, сначала сделайте pg_dump -Fc
локальной базы, затем восстановите его через pg_restore в пустую базу Docker.
При переносе из локальной БД восстановите архив с параметрами
pg_restore --clean --if-exists --no-owner --no-acl поверх автоматически
созданной демонстрационной базы. Это заменит seed содержимым архива.
Не используйте docker compose down -v для обычной остановки: это удаляет данные.

После запуска JavaFX читает параметры БД из корневого .env. SQL и правила
не находятся в обработчиках кнопок: интерфейс вызывает сервисы КР1, а они
работают с JDBC DAO клиента. Поиск и статистика также выполняются через JDBC.
Редактирование и удаление доступны только для заявки CREATED без доставщика.
Экспорт CSV сохраняет текущую выборку, путь выбирается в FileChooser.

Ручная интеграционная проверка создаёт временную заявку и удаляет её:
  cd javafx-client
  mvn test-compile dependency:build-classpath -Dmdep.outputFile=target/runtime-classpath.txt
  java -cp "target/test-classes;target/classes;<содержимое runtime-classpath.txt>" com.lcorp.javafx.DesktopJdbcCheck
