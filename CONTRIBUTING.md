# Участие в проекте

Logistics Company разрабатывают четыре человека. Все КР входят в один проект, поэтому изменения должны сохранять общую архитектуру и рабочее состояние репозитория.

Перед началом прочитайте [контекст](docs/PROJECT_CONTEXT.md), [требования](docs/REQUIREMENTS.md), [архитектуру](docs/ARCHITECTURE.md), [решения](docs/DECISIONS.md) и [backlog](docs/TASKS.md). Уточните этап и границы задачи в её описании. Текущий этап — foundation; реализация КР1 ещё впереди.

## Работа над задачей

1. Проверьте текущую ветку и `git status`; сохраните существующие локальные изменения.
2. Выберите одну задачу и создайте отдельную ветку от актуального `main`. Прямые изменения `main` запрещены.
3. Делайте небольшие логические коммиты и небольшие PR. Используйте Conventional Commits: `feat:`, `fix:`, `refactor:`, `docs:`, `test:`, `chore:`.
4. Меняйте только связанный с задачей код. Согласуйте затрагиваемые общие файлы с командой, чтобы снизить риск конфликтов; не перерабатывайте чужой код без необходимости.
5. Выполните доступные проверки сборки и тесты. Сейчас Maven-проект находится в корне: `mvn -B test`. Требования среды и дополнительные команды описаны в [DEVELOPMENT.md](docs/DEVELOPMENT.md).
6. Проверьте diff и откройте Pull Request с описанием причины, изменений и результатов проверок. Отдельно укажите ограничения среды или невыполненные проверки.
7. Исправьте замечания review и конфликты до merge. Если в GitHub настроено обязательное review, требуется минимум один одобряющий review другого участника.

Подробности обновления веток и завершения PR — в [GIT_WORKFLOW.md](docs/GIT_WORKFLOW.md). Не выполняйте force push в общие ветки и не переписывайте чужую историю.

## Качество и общие файлы

- Java 21 для КР1–КР3; Android пишется на Java с source compatibility 17.
- Используйте UTF-8 и настройки `.editorconfig`; проект не привязан к одной IDE.
- Сохраняйте границы UI → Service → Repository. SQL не размещается в UI, бизнес-правила не дублируются в клиентах.
- Не добавляйте функциональность следующих КР в текущую задачу. JavaFX КР2 использует JDBC напрямую; Android КР4 обращается только к REST backend.
- Не выполняйте массовое форматирование и не добавляйте библиотеки без необходимости.
- Обновляйте docs при изменении архитектуры, способов запуска или требований. Архитектурные решения фиксируйте в `docs/DECISIONS.md`.

## Что нельзя коммитить

Реальные пароли, JWT secrets и токены, `.env`, локальные данные PostgreSQL, логи, `target/`, Android/Gradle build-артефакты и локальные IDE-настройки не должны попадать в Git. Для примеров используйте безопасные placeholder в `.env.example`. Не удаляйте уже существующие пользовательские настройки: новые локальные файлы оставляйте вне коммита, руководствуясь `.gitignore`.

До `git commit` просмотрите `git diff --cached`; после коммита проверьте его состав. Не включайте несвязанные пользовательские изменения.
